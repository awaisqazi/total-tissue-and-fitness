# Cutover content audit: Webflow site vs. Astro site (2026-10-03)

Scope: content, links, facts, routes, embeds and scripts only. Design isn't judged here.

## Evidence

- **Old site:** crawled live from `https://www.totaltissueandfitness.com` with curl (desktop Chrome user agent) on 2026-10-03. Curl wasn't blocked. All three live pages match `docs/source-snapshot/` (captured 2026-09-08) byte for byte, so the snapshot is still an accurate record of the old site.
- **New site:** built from commit `957994e` with `SITE_URL=https://www.totaltissueandfitness.com BASE_PATH=/ PUBLIC_SITE_INDEXABLE=true npm run build`. The rendered pages in `dist/` were compared with the old pages.
- **Route discovery:** every `href` on all three old pages was parsed. Common Webflow and legal paths were probed directly: `/privacy-policy`, `/privacy`, `/terms`, `/terms-of-service`, `/terms-and-conditions`, `/legal`, `/about`, `/contact`, `/services`, `/faq`, `/blog`, `/book`, `/booking`, `/pricing`, `/team`, `/careers`, `/home`, `/search`, `/mentorship`, `/contrast`, `/401`, `/404`, `/sitemap.txt` and `/sitemap_index.xml`. Every probe returned 404.

## Before cutover: items that need a fix or an owner decision

**No old page, old URL or anchor is missing from the new site, and no old URL will 404.** No contact fact on the new site contradicts something the old site published, except the city change in item 3, which the owner approved. The remaining items are decisions or fixes to make before the DNS change:

1. **Jane booking notice dropped (owner must confirm).** Every old page has this two-line announcement bar: “New Clients! We have a new company booking system (Jane). All new appointments need to be manually scheduled after your free educational!” and “Existing clients will be transitioning to the new booking system, ‘Jane’ starting November 1st 2026!” The new site doesn't mention Jane anywhere. It routes all booking through Vagaro, and the home page says “Booking works the same way it always has.” ADR-009 and the launch checklist record that Vagaro's first-session listing was switched from Jane to Vagaro. However, no decision entry says the November 1, 2026 Jane migration was cancelled. If Jane is still going live on Nov 1, `/book/`, the FAQs and every CTA will be wrong within four weeks. Josh needs to confirm that Jane is off, or supply the Jane URLs.
2. **Klaviyo onsite script dropped (owner must confirm).** The old home page loads `static.klaviyo.com/onsite/js/VgANuy/klaviyo.js` (company ID `VgANuy`) plus a custom script that submits `.klaviyo-form` elements to the Klaviyo API. The home page markup has no `.klaviyo-form`, but Klaviyo's onsite script can show sign-up popups and forms configured in the Klaviyo dashboard and can identify visitors. The new site loads no Klaviyo code. Before cutover, Josh needs to confirm whether any Klaviyo sign-up form, popup, flow or list growth depends on the site. If one does, an approved and documented replacement is needed. Otherwise the removal can be recorded as intended.
3. **Old brand name has no search continuity.** The old home page's title, `og:title`, `twitter:title` and meta description all use **“JB-Total Tissue Havoc”** with “Oswego, IL”. Anyone searching that exact name gets no match on the new site. The JSON-LD `alternateName` lists only “Total Tissue & Fitness”, and “Havoc” appears nowhere in `src/`. The owner should decide whether “JB-Total Tissue Havoc” is a real former trading name worth adding as an additional `alternateName`, or a name to let go.
4. **The privacy page will publish pre-launch wording on the live domain.** `/privacy/` says it “does not replace an approved production privacy policy” and that “A production privacy contact will be added before the site launches.” After cutover, that second sentence is false and reads as a placeholder (see the CLAUDE.md guardrail). The old site had no privacy page, so this isn't a parity loss. It does need owner-approved wording, or a recorded acceptance, before launch.
5. **The contact form needs the production hostname to work.** This is already recorded as unresolved in ADR-015. The Turnstile widget and Worker must accept `www.totaltissueandfitness.com` before `/contact/` works on the domain. The page shows a call-us fallback until then. A local build without `PUBLIC_CONTACT_ENDPOINT` renders “The inquiry form is temporarily unavailable.” The deploy workflow sets that variable, so this message only appears in local builds.

### Before cancelling Webflow (not a DNS blocker)

- **Export Webflow form submissions.** The old `/mentorship-program` form (`wf-form-Contact-1-Form`: Name, Email, “What is your Profession?”, Message, Terms checkbox) submitted to Webflow's own form backend. Any past mentorship inquiries exist only in the Webflow project and will be lost when it is cancelled.
- **Old CDN URLs.** Assets on `cdn.prod.website-files.com/65f1cd38d5c13f0914954f48/…`, including the old share image `66269de21a2f67537f7148ac_JB FINAL-webflow.jpg`, keep working only while the Webflow site exists. Local copies are in `public/images/`.
- **Old booking and survey destinations stay live.** The two Calendly event pages (`calendly.com/contrast-therapy/contrast-therapy-clone` and `calendly.com/thayercfitness/total-tissue-session-clone`) and the LeadConnector survey (`api.leadconnectorhq.com/widget/survey/sewamW1vizGBQSxW4B0D`) all returned 200 today. The new site no longer links them, but anyone with a saved link can still book or submit through them. Their owners should disable them or keep them on purpose.

## Other observations

- **Testimonial claims are handled inconsistently.** Amanda's “No more pain!” quote was withheld for claim review. The nine republished gallery screenshots, however, contain comparable or stronger outcome statements, a diagnosis mention, and identifiable client handles/names. Consent and claim review should cover the gallery too.
- **The footer links to the fictional dashboard on the production domain** (“Dashboard concept” → `/admin/`, noindex, disallowed in robots). This is consistent with CLAUDE.md (static, fictional, labelled), but it will be publicly reachable from every page of the live business site.
- **GitHub Pages ignores `public/_headers`**, so the security headers it defines won't apply. ADR-015 already notes this.
- **The `awaisqazi.github.io/total-tissue-and-fitness/` preview now 301s to `http://www.totaltissueandfitness.com/`**, which still resolves to Webflow. Until DNS changes, the new site can't be viewed on its production host. Post-cutover route checks (trailing-slash 301s, `/index.html`, 404 page, HTTPS enforcement) must be run live.
